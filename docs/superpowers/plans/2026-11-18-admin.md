# Admin (etapas e aviso de pedidos) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Página `admin.html` para os dois sócios atualizarem status e etapas dos pedidos, e e-mail para eles quando um pedido é criado e quando é pago.

**Architecture:** Segurança no banco (tabela `admins`, `eh_admin()`, regras de leitura para admin e permissão de edição só nas colunas `pedidos.status` e `etapas.feita/nota/atualizado_em`). Página nova no Vite com lógica pura em `src/paginas/admin-dados.js` (testada) e DOM em `admin.js`; o fluxo de entrar da conta vira um módulo compartilhado. Avisos: montagem do e-mail pura em `supabase/functions/_shared/aviso.js` (testada no Node) e envio pela API do Resend sem lançar erro.

**Tech Stack:** Vite, JS sem framework, Supabase (Postgres RLS, Edge Functions Deno), Resend API, `node:test`.

**Spec:** `docs/superpowers/specs/2026-11-18-admin-design.md`

## Global Constraints

- Sem dependência nova. Visual de `src/paginas/conta.css` (superfícies #111, borda #222, laranja só na ação, Sora nos títulos). Funciona a partir de 360 px; teclado e foco visível.
- `admin.html`: `noindex`, fora de menus e do rodapé; leva os partials `a11y-cedo` (sem o rodapé de confiança).
- Todo dado do banco entra no DOM por `textContent`; no e-mail, nome e textos do cliente passam por escape de HTML.
- Erro no aviso nunca interrompe `criar-cobranca` nem o webhook.
- Chaves (`RESEND_API_KEY`, `ADMIN_EMAILS`) só como segredos do Supabase, cadastradas pelo Kevin; mudanças hospedadas (db push, deploy de função) só com o sim dele.
- Commit por tarefa na branch `admin`; push só quando o Kevin pedir.

## Review Focus

- Usuário logado que não é admin abrindo `admin.html` (ou chamando a API): vê "Sem acesso", nenhuma linha de outro cliente volta do banco.
- Admin tentando mudar `valor`/`forma`/`cobranca` pela API: o banco recusa (permissão por coluna).
- Resend fora do ar ou chave ausente: pedido é criado e pagamento confirmado normalmente; só um `console.error`.
- `admin.html#pedido=<id>` de pedido inexistente: abre a lista, sem erro.
- Pedido de cliente sem linha em `clientes` (não deveria existir, mas): ficha mostra "Cliente sem cadastro" em vez de quebrar.
